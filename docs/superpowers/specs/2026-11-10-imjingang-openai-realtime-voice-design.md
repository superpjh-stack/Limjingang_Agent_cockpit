# 임진강김치 OpenAI Realtime 음성 에이전트 고도화 설계

## 1. 목적과 범위

임진강김치 V2에 이미 들어 있는 OpenAI Realtime WebRTC 기능을 기반으로, 제조 현장에서 ChatGPT에 가까운 한국어 실시간 음성 대화를 제공한다. 사용자는 마이크에 자연스럽게 말하고, 에이전트의 답변 중 끼어들 수 있으며, 현재 임진강김치의 LOT·품질·CCP·재고·문서 근거를 조회할 수 있어야 한다.

이번 범위는 기존 V2의 음성 세션과 제조 도구를 운영 수준으로 고도화하는 것이다. AWS AgentCore/Transcribe/Polly로 음성 경로를 교체하지 않는다. V3의 AWS 음성 설계는 별도 배포 선택지로 남기되, 이번 구현의 기준은 서버 키를 보관하는 FastAPI와 브라우저 WebRTC를 사용하는 OpenAI Realtime 방식이다.

성공 기준:

- 마이크 권한, 연결, 발화 감지, 답변 음성, 끼어들기, 종료가 하나의 흐름으로 동작한다.
- 음성 질문과 답변이 기존 문자 대화 목록에 표시된다.
- 현재 LOT와 연관된 조회 도구만 서버에서 실행된다.
- 답변에 단위, KST 시각, 자료 기준일, `근거:`가 포함된다.
- 승인 배합표·제조표준서·실제 생산기록이 없으면 추측하지 않고 `미확인`으로 답한다.
- 음성 실패 시 문자 질문과 기존 근거 패널은 계속 사용할 수 있다.
- 브라우저 번들·응답·로그에 OpenAI API 키, DB URL, 내부 자격증명이 노출되지 않는다.

## 2. 현재 기준과 발견 사항

현재 저장소에는 다음 기반이 있다.

- `v2/api.py`: `/api/realtime/session`, `/api/realtime/tool`, AI 접근 코드, 읽기 전용 도구 호출
- `v2/web/src/hooks/useRealtimeVoice.ts`: WebRTC, 데이터 채널, VAD 이벤트, 음소거·종료·끼어들기 기반
- `v2/web/src/components/Assistant.tsx`: 실시간 음성 패널, 자막 대화, 문자 fallback, 근거 패널
- `imjingang_agent/factory_tools.py`: 제조 데이터 도구 정의와 실행 경계
- `v2/tests/`: API·도구·접근 제한·UI 회귀 테스트

따라서 신규 음성 앱을 만들지 않고, 현재 구현의 다음 결함을 보완한다.

1. 실시간 음성 대화의 턴과 문자 대화·근거 보존이 완전히 같은 기록 경로로 묶이지 않는다.
2. 세션 시작 시 큰 문맥 스냅샷을 주입하고 있어 최신 데이터 조회 원칙과 충돌할 수 있다.
3. 음성 도구 허용 목록, 인자 검증, 호출 오류의 구조화 응답을 더 명확히 해야 한다.
4. 응답 중 끼어들기·늦게 도착한 이벤트·세션 종료 후 결과 처리의 회귀 테스트가 부족하다.
5. 모바일 실기기, HTTPS, 자동재생 차단, 공장 소음에 대한 검증 절차가 문서화되어야 한다.

## 3. 선택한 접근

### 채택: OpenAI Realtime WebRTC + FastAPI 읽기 전용 도구

```text
브라우저 마이크/스피커
        │ WebRTC 오디오 + DataChannel 이벤트
        ▼
FastAPI /api/realtime/session
        │ 서버 키·접근 코드·LOT 문맥·도구 정의
        ▼
OpenAI Realtime
        │ function_call_arguments.done
        ▼
FastAPI /api/realtime/tool
        │ 도구명·인자 검증
        ▼
임진강김치 읽기 전용 데이터/문서 계층
```

OpenAI API 키는 FastAPI 서버에만 둔다. 브라우저는 WebRTC SDP와 same-origin 도구 호출만 사용한다. 브라우저에서 임의 SQL, 임의 URL, 데이터베이스 접속정보를 받지 않는다.

STT→LLM→TTS 연결형은 문자 fallback과 배치형 음성 입력에 유지하지만, 실시간 기본 경로로 사용하지 않는다. AWS AgentCore 음성 경로는 이번 범위에 포함하지 않는다.

## 4. 대화와 음성 동작

### 세션 시작

1. 브라우저가 HTTPS 또는 localhost에서 마이크 권한을 요청한다.
2. `/api/realtime/session`이 접근 코드를 확인하고 SDP를 OpenAI에 전달한다.
3. 서버는 임진강김치 전용 시스템 지침과 현재 선택 LOT 식별자만 세션에 설정한다.
4. 최신 제조값은 시작 시 전체 스냅샷으로 확정하지 않고, 회사 기록 질문에 대해 도구로 조회한다.

### 발화와 응답

- 의미 기반 VAD를 사용하고, 발화 종료 후 자동으로 응답한다.
- 입력 오디오에는 echo cancellation, noise suppression, auto gain control을 적용한다.
- 사용자 발화의 확정 전사는 UI와 대화 기록에 표시한다.
- 답변 음성은 짧고 자연스러운 존댓말로 말한다.
- 답변 텍스트는 화면에 함께 표시하고, 조회 기록·문서는 근거 패널에서 펼친다.
- 중요한 LOT 번호, 수량, 날짜는 한 번 짧게 재확인한다.

### 끼어들기

- Realtime의 `interrupt_response`를 활성화한다.
- 새 발화가 감지되면 현재 음성 재생을 멈추고 이전 답변의 누적 텍스트를 확정하지 않는다.
- 늦게 도착한 오디오·도구 결과는 세션 epoch와 call ID로 폐기한다.
- 사용자가 새 질문을 끝내면 이전 답변이 아닌 새 질문만 처리한다.

## 5. 제조 근거와 도구 경계

음성 모델에는 현재 임진강김치 업무에 필요한 최소한의 읽기 전용 도구만 등록한다.

- `get_lot_trace`: 원료 LOT→제조 LOT→포장 LOT
- `get_recipe_requirements`: 승인 배합표 버전과 기준량에 따른 소요량
- `get_inventory_status`: 사용 가능·예약·품질보류 재고
- `get_process_measurements`: 공정 측정값과 측정 시각
- `get_ccp_deviations`: CCP 기준·실측·이탈 상태
- `get_quality_status`: 품질검사와 검사 대기 상태
- `get_shipment_readiness`: 출하 전 확인 기록
- `search_knowledge`: 승인된 제조·품질 문서 검색

도구 계약은 다음 원칙을 따른다.

- 서버 소유의 좁은 함수만 노출한다.
- LOT ID, 날짜 범위, limit, 기준량을 Pydantic으로 검증한다.
- 결과에는 원본, 기준일, KST 시각, 단위, 문서 개정번호를 보존한다.
- 데이터가 없거나 최신 여부가 확인되지 않으면 `미확인`을 반환한다.
- 상류 시스템 오류는 구조화된 오류로 반환하고 모델이 장애를 성공 결과로 설명하지 않게 한다.
- 도구 호출은 call ID를 deduplicate하고 세션 종료 후 결과를 무시한다.

다음 동작은 제공하지 않는다.

- 배합표·공정조건 수정
- 생산중지·출하승인·제품폐기
- 재고 차감·작업지시 실행
- 임의 DB 수정 또는 설비 제어

## 6. 답변 정책

음성 응답은 보통 3문장 이내로 한다.

1. 확인 결과를 먼저 말한다.
2. 필요한 경우 담당자 확인사항을 말한다.
3. 화면 근거를 안내한다.

예시:

> “임진감김치 포장 LOT의 CCP 기록을 확인했습니다. 기준 이탈 1건이 있어 담당자 확인이 필요합니다. 측정값과 기준 문서는 화면의 근거에서 확인할 수 있습니다.”

승인 배합표·제조표준서·실제 생산기록은 프로젝트에 제공된 승인 자료를 우선한다. 자료가 없는 수치, 온도, 시간, 염도, pH, 소비기한을 임의로 확정하지 않는다. 샘플 데이터는 항상 샘플 기준일과 함께 표시한다.

## 7. 프런트엔드 변경 설계

수정 대상:

- `v2/web/src/hooks/useRealtimeVoice.ts`
  - 세션 epoch, call ID, 응답 ID의 수명 관리 강화
  - 확정 사용자 전사와 답변 텍스트를 동일한 turn 계약으로 전달
  - 음성 재생 실패·자동재생 차단·재연결 상태를 분리
  - 세션 종료 시 미완료 fetch와 오디오 트랙 정리
- `v2/web/src/components/Assistant.tsx`
  - 음성 턴을 기존 메시지·근거 패널과 연결
  - 듣는 중/조회 중/답변 중/중단 상태의 명확한 표시
  - 음성 실패 시 문자 입력을 즉시 활성화
  - 현재 LOT와 샘플 데이터 안내를 음성 패널에 표시
- `v2/web/src/types.ts`
  - 음성 turn, 응답 ID, 근거 보존 상태 타입 추가
- `v2/web/src/` 관련 CSS
  - 48px 터치 영역, reduced-motion, 모바일 세로·가로 화면, 키보드 포커스 보장

문자 질문과 음성 질문은 가능한 한 동일한 답변·저장 경로를 사용한다. 실시간 음성의 자막만으로 업무 근거를 자동 확정하지 않고, 도구 결과와 답변 텍스트를 함께 보존한다.

## 8. 백엔드 변경 설계

수정 대상:

- `v2/api.py`
  - 임진강김치 전용 음성 지침 정리
  - 실시간 음성 도구 allowlist 명시
  - 도구 입력과 출력의 구조화 오류 처리
  - 최신값은 도구 조회를 우선하고, 세션 시작 문맥은 식별자·기본 규칙으로 제한
  - 접근 코드와 로컬 loopback 예외를 기존 정책대로 유지
- `imjingang_agent/factory_tools.py`
  - 음성에서 사용 가능한 도구 정의와 인자 제한 검토
  - 승인 배합표·LOT·품질·CCP 근거 필드의 단위와 기준일 통일
- `v2/tests/test_api.py`
  - 세션 설정, 키 비노출, 허용/비허용 도구, 인자 오류, 구조화 실패 검증

외부 데이터 연동이 설정되지 않은 환경에서는 도구가 조회했다고 가장하지 않는다. 로컬 데모 데이터는 `demo_data`와 기준일을 답변 메타데이터에 표시한다.

## 9. 검증 계획

### 자동 검증

- V2 API 테스트 전체
- 음성 세션의 모델·도구 allowlist 테스트
- 잘못된 LOT·날짜·limit 거절 테스트
- 도구 오류·빈 결과·미확인 답변 테스트
- 중복 call ID와 늦은 결과 폐기 테스트
- 번들·응답에 API 키와 DB URL이 없는지 검사
- `npm run build --prefix v2/web`

### 브라우저 검증

- Chrome desktop: 연결, 음성 질문, 도구 조회, 끼어들기, 종료
- Chrome Android HTTPS: 마이크 권한, 화면 잠금·복귀, 자동재생
- Safari iPhone HTTPS: 마이크 권한, 답변 재생, 백그라운드 전환
- 공장 소음 조건: 짧은 LOT 번호, 숫자·단위, 재질문
- 음성 실패 후 문자 질문과 근거 패널 사용

### 품질 지표

- 음성 세션 연결 성공률
- 첫 음성 응답 시간 P50/P95
- 사용자의 끼어들기 성공률
- 확정 전사 완료율
- LOT·수량·단위 전사 정확도
- 근거 도구 호출 답변 비율
- 미확인 데이터 추측 0건
- 음성 실패 후 문자 전환 성공률

실제 OpenAI 자격증명·HTTPS·마이크가 없는 환경에서는 자동 테스트 통과를 음성 품질 완료로 보고하지 않는다.

## 10. 단계별 구현 순서

1. 현재 V2 음성 경로와 임진강김치 도구 계약의 회귀 테스트 추가
2. 세션 지침·도구 allowlist·최신 조회 원칙 정비
3. 음성 turn과 근거 기록을 문자 대화 경로에 연결
4. 끼어들기·늦은 이벤트·재연결·자동재생 오류 보강
5. 모바일·접근성 UI 보강
6. 자동 테스트·프런트 빌드 실행
7. 설정된 자격증명으로 실제 read-only 도구 호출 확인
8. HTTPS 데스크톱·Android·iPhone 실기기 검증

## 11. 제외 범위

- 임진강김치 승인 배합표를 임의로 생성하거나 변경하는 기능
- 실시간 센서·MES·ERP가 연결되지 않은 상태에서의 운영값 추정
- 음성으로 생산·출하·설비를 자동 실행하는 기능
- AWS AgentCore 음성 Runtime으로의 이전
- 음성 원본 오디오 장기 저장
- 사용자 승인 없는 외부 전송

## 12. 미확정 사항

구현 전 다음 자료는 현장 기준으로 확인해야 한다.

- 승인 배합표 문서명·개정번호·기준 배치량
- 제조표준서와 CCP 기준 문서
- 실제 운영 DB 또는 API의 접속 계약
- 임진감김치 LOT 식별 규칙
- 음성 사용자의 역할별 접근 범위
- 현장 테스트 장소와 HTTPS 접속 주소

위 항목이 제공되기 전까지 샘플 데이터와 문서의 상태는 제조 검토용 데모로 유지한다.
