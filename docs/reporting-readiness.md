# 임진강김치 V3 보고서 기능 준비안

상태: 설계·자료 준비안. 보고서 생성 기능과 아래 입력 테이블은 아직 구현되지 않았다.
작성일: 2026-11-12. 현재 연결 DB는 가상·미승인 샘플이며 공식 실적으로 사용하지 않는다.

## 목표와 우선순위

사용자가 “어제 제품별 일일실적표 만들어줘”라고 요청하면 기간·사업장·집계 기준을 확인하고, 근거가 연결된 미리보기와 Excel/PDF 파일을 제공한다. 수치 집계는 서버에서 계산하고 AI는 설명·특이사항 요약만 작성한다.

1. 일일 생산실적표: 제품·규격·라인·교대별 계획, 양품 실적, 불량, 달성률, 특이사항.
2. 품질·CCP 일보: 검사 건수, 판정, 이탈 항목, 조치 상태. 검사 건수와 불량 제품 수량은 별개다.
3. 출하 실적표: 실제 출하 기록, 거래처·제품·LOT별 수량. 승인/예정 물량은 별도 표시한다.
4. 재고 현황표: 조회 시점 재고, 기준 재고 대비 부족량. 과거 일자 마감 재고는 이력이 확보된 후 제공한다.
5. 주간·월간 보고서: 동일한 집계 기준이 확보된 뒤 기간 비교와 추세를 추가한다.

Excel부터 시작하고 PDF를 추가하는 방안은 수치 검토와 현장 양식 조정에 유리하다. Excel/PDF 동시 제공은 편리하지만 인쇄 레이아웃 검증이 추가로 필요하다. 처음부터 정시 생성·메일 발송까지 연결하는 방안은 마감·수신자·권한 관리가 필요하므로 후속 단계로 둔다. 권장 첫 범위는 요청형 일일실적표의 미리보기와 Excel/PDF 다운로드이며 자동 발송은 포함하지 않는다.

## 현재 DB와 준비할 데이터

| 보고 항목 | 현재 원본 | 사용 조건 / 부족한 점 |
|---|---|---|
| 제품·공정·LOT·수량 | lots | created_at은 등록 시각. 완료 실적으로 간주할 수 없음 |
| 공정 측정값 | process_measurements | measured_at 기준. weight_kg를 생산 실적으로 임의 대체하지 않음 |

| 출하 | shipments | shipped_at, approval_status가 실제 완료를 뜻하는지 확인 필요 |
| 현재 재고 | inventory | updated_at을 표시. 과거 마감 재고와 입출고 변동 이력 없음 |
| 계획·달성률 | 없음 | 제품·라인·교대별 확정 계획과 계획 버전 필요 |
| 양품·불량·재작업 | 없음 | 완료 이벤트별 수량과 중복 제거 기준 필요 |

| 조치·작성·검토 상태 | 일부 없음 | 담당자, 조치 내용, 검토자와 검토 이력 필요 |

## 자료 수집 체크리스트

필수 준비 자료:
- 현재 사용하는 일일실적표 원본 양식 1개. 없으면 아래 기본 양식으로 시작한다.
- 최근 3~7일의 실제 생산실적 원본. 원본 행 ID, 완료 시각, 제품 코드, LOT, 양품 수량, 단위 포함.
- 같은 기간의 확정 생산계획. 없으면 계획·달성률은 미집계로 표시한다.
- 제품 코드·제품명·규격·단위 및 kg/봉/박스 환산 기준. 환산 기준에는 적용 기간도 필요하다.
- 일자 마감 시각과 교대 기준: 예시 00:00~24:00 또는 전일 08:00~당일 08:00 중 회사 기준을 확인한다.
- 불량·폐기·재작업 구분, 취소·정정 기록의 처리 규칙.

확장 시 자료:
- 품질 및 CCP 검사·조치 기록, 실제 출하 완료 기록, 재고 수불·마감 스냅샷.
- 작업시간·비가동·작업인원, 보고서 로고와 작성/검토 표시 방식.
- 조회 권한과 파일 보관 기간. 자동 발송은 별도 명시적 요청 후 수신자를 설정한다.

초기 제출 자료에는 불필요한 개인정보·API 키·접근 코드를 포함하지 않는다.

## 입력 데이터 계약 초안

생산 완료 실적: `record_id`, `completed_at`, `business_date`, `site_id`, `line_id`, `shift_id`, `product_code`, `lot_id`, `good_qty`, `reject_qty`, `unit`, `status`, `source_id`, `revision`, `updated_at`.

생산계획: `plan_id`, `business_date`, `site_id`, `line_id`, `shift_id`, `product_code`, `planned_qty`, `unit`, `plan_version`, `approval_status`.

제품 기준: `product_code`, `product_name`, `specification`, `base_unit`, `kg_per_unit`, `units_per_box`, `effective_from`, `effective_to`.

불량은 사유별 별도 상세표에 `defect_record_id`, `production_record_id`, `defect_type`, `quantity`, `unit`, `disposition`을 둔다. 같은 불량 수량을 상세와 합계에서 중복 합산하지 않는다. kg 기준인 항목은 환산계수가 필요 없으며, 다른 단위는 승인된 제품별 환산계수 없이는 합산하지 않는다.

## 일일실적표 기본 양식

머리말: 회사명 / 대상 업무일과 시간대 / 공장·라인·교대 / 조회 시각 / 원본 기준 시각 / 보고서 ID·버전 / 초안·검토 상태.

요약: 계획량, 양품 생산량, 달성률, 불량량, 불량률, 출하량. 자료가 없는 항목은 ‘미집계’로 표시한다.

| 제품 코드·제품명 | 규격 | 라인·교대 | 계획(kg) | 양품(kg) | 불량(kg) | 달성률(%) | 불량률(%) | LOT | 특이사항 |
|---|---|---|---|---|---|---|---|---|---|
| 원본에서 조회 | 원본에서 조회 | 원본에서 조회 | 미집계 가능 | 완료 기록 기준 | 미집계 가능 | 기준 확정 후 계산 | 기준 확정 후 계산 | 원본 연결 | 사실·추정 구분 |

하단: 품질·CCP 이탈과 조치, 출하·재고 참고, 미집계 항목, 원본 행과 근거, 작성·검토 정보.

권장 Excel 시트: 일일실적표 / 생산상세 / 품질·CCP / 출하상세 / 근거·집계기준.
PDF는 요약과 표를 인쇄용으로 구성하고 페이지마다 대상 일자·단위·초안 상태를 표시한다.

## 집계 원칙

- 한국 시간 기준 기간 [시작, 종료)로 조회한다. ‘어제’도 실제 날짜와 시간 범위를 미리보기에 표시한다.
- 생산실적은 승인된 완료 이벤트와 공정 범위로 집계한다. 원료·절임·발효·포장 계보를 모두 더하지 않는다.
- 제안 달성률 = 양품 실적 / 확정 계획 × 100. 제안 불량률 = 불량 / (양품 + 불량) × 100. 회사 정의 확인 전 고정하지 않는다.
- 계획 미등록과 계획 0을 구분한다. 분모 0 또는 누락 시 비율은 ‘산출 불가’이며 0%가 아니다.
- 합계 비율은 행별 비율 평균이 아니라 합계 분자/합계 분모로 계산한다.
- 서로 다른 단위를 그대로 합산하지 않는다. 반올림은 계산 후 표시 단계에 적용한다.
- 재작업·취소·정정은 원본 ID와 버전으로 처리한다. 정정 전후 보고서는 버전으로 구별한다.
- 자료 없는 날짜는 ‘자료 없음’. 조회 실패는 ‘조회 실패’. 전체 수집 완료가 검증되지 않으면 0실적으로 확정하지 않는다.
- 과거 재고는 일별 스냅샷 또는 검증된 수불 이력이 있어야 산출한다.
- AI는 집계 수치를 수정하거나 미등록 실적·원인을 보완하지 않는다. 특이사항 추정은 별도 표기한다.

## 요청부터 다운로드까지

요청 해석 → 기간·사업장·단위 확인 → 읽기 전용 조회 → 서버 집계 → 합계·중복·누락 검사 → 설명 작성 → 미리보기 → Excel/PDF 다운로드.

LangGraph에는 보고서 요청 분기와 집계·검사 노드를 추가한다. 화면에는 ‘보고서 만들기’, 대상 기간, 보고서 종류, 다운로드 버튼을 둔다. 기존 대화·연구소는 유지한다. 파일은 화면과 동일한 집계 결과 스냅샷에서 생성해 값이 달라지지 않도록 한다. XLSX의 외부 입력은 문자열로 기록해 수식으로 실행되지 않게 한다.

예시 요청:
1. 어제 제품별 일일실적표를 엑셀로 만들어줘.
2. 9월 3일 생산실적과 계획 달성률을 비교해줘.
3. 이번 주 CCP 이탈과 조치 내역을 PDF로 정리해줘.
4. 거래처별 실제 출하량과 출하 대기를 나눠줘.
5. 오늘 조회 시점의 재고 부족 목록을 보고서로 만들어줘.

## 완료 검증 기준

- 자정·교대 경계, 단위 변환, 취소·정정·재작업·중복 이벤트 검증.
- 계획 없음/0, 부분 누락, 조회 실패, 자료 없는 기간을 각각 구분.
- 원본 합계 = 미리보기 = Excel = PDF 수치 일치.
- PDF 한글·페이지 나눔·긴 제품명·합계행 검증, 모바일 다운로드 확인.
- 사용자 권한별 조회 및 파일 다운로드 범위 일치, 샘플 보고서에 샘플 표시.

우선 확인할 결정: 기존 양식 사용 여부, 생산실적의 완료 공정·기준 시각, 단위, 계획/불량 데이터의 제공 가능 여부. 실제 자료가 확보되기 전에는 샘플 보고서 또는 미집계 항목을 명시한 초안까지만 제공한다.

## 제공된 실제 양식 분석 — 2026-11-12

사용자가 제공한 평창꽃순이김치 파일 2개를 OOXML 읽기 전용으로 확인했다. 원본은 수정하지 않았으며, 임진강김치 DB로 실적·고객·담당자 데이터를 가져오지 않았다. 아래는 양식 적용을 위한 매핑이며 생성 기능 구현은 아직 아니다. 인쇄 설정은 파일에서 확인했으나 Excel/PDF 시각 검증은 생성 단계에서 수행해야 한다.

### 완제품 및 포장 생산 일지

원본: `26년 09월 일별 생산보고서- 완제품.xlsx`. 일자 시트 21개와 `서식` 시트, 총 22개. 기본 템플릿 후보는 `서식!A1:AD63`, A4 세로. 날짜별 품목 수에 따라 행수와 인쇄 범위가 달라진다.

| 영역 | 셀/구조 | 입력·계산 방식 |
|---|---|---|
| 제목·작성/검토/승인 | B1, U1:AC3 | 회사별 제목 변경 가능. 원본 담당자·서명은 복사하지 않음 |
| 업무일 | E3, H3, N3 | 연도·날짜·요일을 같은 보고일에서 생성 |
| 근무시간 | E5 | 출퇴근 범위만으로 순작업시간을 계산하지 않음 |
| 일생산목표 | V5 = AA6*270 | 원본은 총근무자 × 270. 임진강김치 목표 기준은 별도 확인; 270을 이식하지 않음 |
| 인원·공정 배치 | 6~7행 | 여성·남성·일용·결근조퇴·총근무자 및 절임/양념/생산/포장/설비 인원. 각 항목 정의 확인 필요 |
| 환경·검사 | 8행 | 냉장실 6곳, 작업장 온도, 금속검출 판정. 데이터가 없으면 미입력 |
| 포기김치 생산 | 서식 12~45행 | 품목 C, 규격 H, 개수 K, 생산kg N. 2행 단위로 절임·양념 사용량(T)과 LOT(V)를 표시 |
| 기타김치 생산 | 서식 48~59행 | 품목·규격·개수·생산kg, 혼합 LOT(S), 시작(V)/종료(Z), 비고(AC) |
| 생산량 계산 | 예: N12 = K12*H12 | 규격 kg/ea × 개수 ea. 빈 입력은 실적 0으로 확정하지 않음 |
| 요약 | 서식 61~63행 | 포기김치·기타김치·캔류 기타·홈쇼핑 및 당일 총량. 목표 달성률 표시 칸 존재 |

기존 제안의 계획/불량 중심 기본 양식보다 제공 양식의 구성을 우선한다. 불량·출하·재고 등의 추가 분석은 별도 상세 또는 화면에서 제공하며 원본 일지에 임의로 열을 늘리지 않는다.

확인된 문제 및 처리:
- `09.20!G39`는 `SUM(#REF!)`, `G41`에도 오류가 전파된다. 원본을 임의 수정하지 않고 생성용 사본의 해당 상세 범위로 합계를 재구성한다.
- `09.30!G45`는 `SUM(N12:Q15)`여서 포기김치 구역의 N16/N18이 포함되지 않는다. 두 행의 포함 여부를 업무 기준과 대조해야 하며 기존 합계의 정확성을 가정하지 않는다.
- 일부 품목명이 비어 있는 다음 규격 행이 있다. 앞 품목을 이어 쓴 것인지 확인 후 제한적으로 보완하며 다른 구역으로 전파하지 않는다.
- 날짜·반제품 LOT가 Excel 날짜 값인 경우가 있다. 원본 서식과 의미를 확인하고 실제 제조 LOT 코드와 구분한다.
- 공통 Print_Area 정의에 #REF!가 있어 생성 파일에서는 유효한 시트별 인쇄 범위를 설정한다.

### 출고요청서

원본: `0617-출고요청서.xlsx`. `원본양식` 및 거래처/배송 구분 시트 등 총 16개. 기본 템플릿 후보는 `원본양식!A1:K33`, A4 세로.

| 항목 | 셀 | 준비할 입력 |
|---|---|---|
| 제목 | B2 | 출고요청서 및 선택한 배송 구분 |
| 출고일·요일 | D4, G4 | 요청 출고일, 날짜에서 계산한 요일 |
| 출고자 | I4 | 임진강김치 담당자, 없으면 공란 |
| 작성일·요일 | D6, G6 | 작성일, 날짜에서 계산한 요일 |
| 작성자 | I6 | 확인된 작성자 |
| 거래처 | D8 | 거래처 코드와 명칭 |
| 구분 | I8 | 택배 / 배송 / 방문 |
| 품목 행 | 12~32행 | B 순번, C 품명·원산지, E 규격(kg), F 단위, G 수량(ea), H 합계kg, I 비고, J 제조일자 |
| 회사명 | H33 | 대상 회사의 확인된 명칭으로 교체 |

중량 = 규격(kg/ea) × 수량(ea). 원본에 공유 수식이 있으므로 값만 추출해서 수식을 없애지 않는다. 30~32행에는 H열 계산식이 없어서 모든 사용 행을 일관되게 계산하도록 생성 로직을 구성한다. 빈 날짜의 WEEKDAY가 요일로 보이지 않도록 빈값 처리를 적용한다. 공통 인쇄 범위 및 자사 시트의 필터 정의에 #REF!가 있어 생성용 사본에서는 유효한 범위를 재설정한다.

요청 예: “내일 ○○거래처에 포기김치 10kg 20개, 깍두기 5kg 10개 배송 출고요청서 만들어줘.”

입력 검증: 거래처·출고일·배송 구분·제품·규격·수량을 확인한다. 규격 미확인 시 총 kg를 추정하지 않는다. 제조일자/원산지는 검증된 제품·LOT 정보가 없으면 비워 두고 미확인 항목으로 안내한다. 복수 LOT/제조일자는 행을 분리한다. 재고 부족은 경고로 표시하되 대체 품목이나 배정을 자동 확정하지 않는다.

요청서 생성은 문서 초안 작성이다. 재고 차감·출고 승인·운송 접수·거래처 발송은 수행하지 않는다. 요청 수량은 실제 출하 실적에 합산하지 않는다.

### 다음에 필요한 최소 자료

양식 2개는 확보했다. 남은 것은 임진강김치 제품 코드/품명/규격(kg/ea), 거래처 목록, 적용할 생산목표 기준, 하루치 생산·근무·온도 기록이다. 출고요청서에 들어갈 요청 수량과 배송 구분은 대화에서도 받을 수 있다. 원산지·제조일자·LOT는 등록 자료에서 확인 가능한 항목만 채운다.

## 샘플 데이터 준비 완료

사용자 요청에 따라 임진강김치용 가상 자료를 각 100건 생성했다. 실제 평창꽃순이김치 자료는 사용하지 않았다.

- `report_sample_products`: 김치 10종 × 규격 10종(0.5~20 kg/ea), 총 100개. 원산지는 미확인(null).
- `report_sample_customers`: 가상 거래처 100개, 채널·지역·배송 구분. 실제 연락처나 개인정보 없음.
- `report_sample_production`: 2026-09-01~09-20, 하루 5건씩 100건. 제품/거래처 참조, 독립 샘플 LOT, 시작·완료 시각, 계획·양품·불량 개수와 kg.
- 모든 행에 company=임진강김치, is_sample=1, source 표기. 제품·규격은 가상 카탈로그이며 실제 판매 제품을 뜻하지 않음.
- 기존 공정 LOT·재고·출하 실적과 별도 테이블로 관리. 거래처 참조는 가상 배정이며 주문·실제 출하를 의미하지 않음.
- 초기화 시 누락된 고정 ID만 삽입. 재시작해도 중복 생성하거나 기존 행을 덮어쓰지 않음.
- 로컬 기본 V2 DB 및 V3 미리보기 DB에 반영. 데이터허브에서 각 100건 조회와 상세 보기 가능. 운영 서버 배포는 별도.

33개 테스트 통과(1개 건너뜀): 수량×규격 일치, 참조 연결, 재실행 중복 방지·기존 행 보존, 조회 API 확인. 보고서 생성 기능은 별도 구현 대상이며 근무인원·환경온도·반제품 사용량은 이번 샘플에 포함하지 않았다. 해당 칸은 추가 입력 전까지 미입력으로 처리한다.
